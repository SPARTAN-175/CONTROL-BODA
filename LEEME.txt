CONTROL DE INVITACIONES DE BODA — PWA OFFLINE

QUÉ INCLUYE
- Importación de Excel .xlsx/.xlsm (lee la primera hoja) y CSV.
- Códigos únicos para identificar cada invitación aunque se repita el apellido.
- Escáner de códigos de barras con cámara cuando el navegador lo admite.
- Búsqueda manual por código, lista de invitados y vista de ocupación por mesa.
- Capacidad predeterminada de 10 personas por mesa, editable.
- Generación e impresión de códigos de barras Code 128, individual o en hoja, con nombre de familia, referencia, mesa, personas y código visible para identificar cada etiqueta.
- Exportación CSV compatible con Excel.
- Datos guardados en el dispositivo; no usa servidor ni envía datos.
- Service worker para cargar la interfaz sin internet después de la primera visita.

CÓMO USAR
1. Sube todos los archivos y carpetas de este ZIP a la raíz de un sitio HTTPS (por ejemplo GitHub Pages). No subas el ZIP comprimido: extrae y sube los archivos; index.html debe quedar en la raíz.
2. Abre el sitio con conexión una vez. En Android, usa Chrome y elige “Instalar aplicación” o “Añadir a pantalla de inicio”.
3. En Datos, importa tu Excel. Los encabezados aceptados incluyen: N°, FAMILIA, NUMERO DE MESA, NUMERO DE PERSONAS, NOMBRE CONOCIDO (REFERENCIA), PERSONAS POR MESAS y CODIGO.
4. Si CODIGO está vacío o repetido, la app asigna BODA-0001, BODA-0002, etc. Exporta invitados y códigos para conservar la lista definitiva.
5. Imprime los códigos desde “Imprimir hoja de códigos”. Verifica que el código impreso coincida con la columna CODIGO antes de pegarlos en las invitaciones.
6. El día de la boda, abre Escanear, permite la cámara y lee el código. La app mostrará familia, referencia, mesa, número de personas y ocupación de la mesa.

IMPORTANTE SOBRE LOS CÓDIGOS
- La app NO puede adivinar qué código ya fue impreso si el código impreso no existe en el Excel. Los códigos generados deben imprimirse desde esta app (o copiarse a la columna CODIGO del Excel) y usarse en las invitaciones.
- La importación XLSX está diseñada para hojas comunes de Excel con encabezados en la primera fila y datos en la primera hoja. Si un archivo no abre, guárdalo desde Excel como CSV UTF-8 e importa ese CSV.
- La cámara web requiere HTTPS o localhost y un navegador compatible con BarcodeDetector. Si el navegador no soporta lectura, usa un Chrome actualizado en Android o introduce el código manualmente.
- “Personas por mesa” se calcula sumando NUMERO DE PERSONAS de todas las invitaciones asignadas a esa mesa; no depende del valor precalculado del Excel.
- La app guarda datos en el almacenamiento local del navegador. No borres los datos del navegador ni cambies de dispositivo sin exportar una copia.
- Los códigos generados por la app son Code 128, adecuados para impresión. No uses una fuente de código de barras en Excel sin convertir el texto a la codificación correspondiente.


INSTALACIÓN / SOLUCIÓN AL PROBLEMA
- No se instala abriendo el ZIP ni haciendo doble clic en index.html. Las PWA necesitan servirse por HTTPS (GitHub Pages sirve HTTPS).
- Extrae TODOS los archivos de este ZIP y súbelos al mismo directorio de tu sitio, manteniendo juntos index.html, app.js, styles.css, sw.js, manifest.webmanifest, icon.svg, icon-192.png e icon-512.png.
- En GitHub Pages, confirma que la URL termine abriendo index.html en la raíz o carpeta del proyecto y que sea HTTPS.
- Abre la URL publicada en Chrome, recarga y espera unos segundos. En Datos aparece “Instalar aplicación”; si Chrome no ofrece instalación automática, usa ⋮ > Instalar aplicación / Añadir a pantalla de inicio.
- La primera apertura debe ser con internet para descargar y guardar los archivos. Luego prueba modo avión. Los datos importados se guardan localmente en el mismo navegador/dispositivo.
- Para actualizar una instalación anterior, reemplaza TODOS los archivos con los de esta versión, abre la URL con internet y recarga dos veces. El service worker v3 elimina la caché anterior de esta aplicación.
- La impresión individual y la hoja de códigos vuelven a mostrar la familia, referencia, mesa, número de personas, código de barras y código legible; así puedes identificar a quién pertenece cada etiqueta.


VERSION 4 — FLUJO PARA PERSONAL DE PUERTA
- El visor de cámara es más compacto; tras leer un código, la pantalla baja automáticamente hasta la ficha de la invitación.
- Al leer un código suena un doble pitido. Un código desconocido emite un tono distinto. El navegador debe permitir audio; el sonido se activa tras la interacción con la cámara/búsqueda.
- La ficha permite registrar cuántas personas de ese pase llegaron ahora, incluso si llegan por separado. Se pide confirmación para evitar toques accidentales, se limita el número al pase autorizado y muestra cuántas faltan.
- Se guarda fecha/hora local del último registro, se puede exportar CSV con el estado de llegada y hay una acción para reiniciar todas las llegadas sin borrar invitados.
- Importante: los registros de llegada son locales a cada dispositivo. Para evitar duplicados cuando haya varios auxiliares, todos deben usar el mismo teléfono. Los dispositivos distintos no sincronizan en modo offline.

CONFIGURACIÓN FIREBASE (OBLIGATORIA ANTES DE USAR VARIOS TELÉFONOS)
El código ya incluye la configuración del proyecto Firebase proporcionada por el usuario y la sincronización Firestore. Para que funcione de verdad, completa una vez estos pasos en Firebase Console:
1. Abre https://console.firebase.google.com/ y selecciona el proyecto control-boda-85fc9.
2. Authentication > Sign-in method > habilita “Correo electrónico/Contraseña”.
3. Authentication > Users > Add user: crea una cuenta individual para cada auxiliar autorizado. Comparte las credenciales solo con el personal de la puerta.
4. Firestore Database > Create database si todavía no existe. Copia las reglas del archivo firestore.rules y publícalas en la pestaña Rules.
5. En Authentication > Settings > Authorized domains, asegúrate de que el dominio de GitHub Pages esté autorizado (si corresponde).
6. Publica todos los archivos de este ZIP en la raíz del sitio HTTPS. Entra a Datos desde el teléfono que tenga la lista definitiva, inicia sesión y pulsa “Publicar lista en Firebase” UNA SOLA VEZ. Los demás teléfonos inician sesión con sus propias cuentas y recibirán la lista automáticamente.
7. Prueba dos teléfonos antes de la boda: registra una persona en el primero y verifica que el segundo actualice el contador.

IMPORTANTE SOBRE CONCURRENCIA Y OFFLINE
- Las llegadas hechas con sesión y conexión usan una transacción Firestore para comprobar el saldo del pase y evitar que dos auxiliares registren más personas de las autorizadas.
- La marca de invitación entregada se sincroniza por Firestore al estar en línea.
- Sin conexión, los cambios son solo locales y no se reflejan en otros teléfonos hasta que se implementa/reconcilia la sincronización. No uses dos teléfonos desconectados esperando prevención instantánea de duplicados.
- El archivo de reglas permite leer/escribir únicamente a usuarios autenticados. No uses reglas públicas de tipo “allow read, write: if true”.
- La configuración web de Firebase (incluida apiKey) identifica el proyecto, pero no sustituye Authentication ni las reglas de Firestore.
- El navegador debe cargar una vez los SDK de Firebase con internet. La app básica y los datos locales continúan disponibles offline; sincronización compartida requiere conexión.
